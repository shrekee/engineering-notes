# 采集易错点：把“看见一条”与“链路可靠”分开

本页描述风险模型和建议检查，不是事故记录，也不是实测结论。所有故障注入仅应在获授权的隔离测试环境执行。

## 1. 文件存在不等于采集器能读到

首先分清三种来源：运行时保存的 stdout/stderr、共享卷中的应用文件、容器可写层中的应用文件。它们的发现、访问权限与生命周期不同。节点代理能读到运行时日志，并不代表能自动读取任意容器内部文件；只挂载公共日志目录也不能证明可写层文件可见。

对于可写层文件，先验证目标运行时和采集器版本是否支持所需发现及路径映射。不要硬编码存储驱动目录或扩大宿主机权限来掩盖不兼容。可考虑把应用日志迁移到明确共享卷，或使用受控 sidecar；这是方案变更，应重新评估生命周期、成本和授权。Kubernetes 官方列出节点代理与 sidecar 两类模式，但没有赋予它们相同的可靠性保证。[日志架构](https://kubernetes.io/docs/concepts/cluster-administration/logging/)

建议先列出“应用看到的文件 → 采集器看到的文件 → 匹配规则 → 可读身份 → 输出目标”的映射，再检查正反例。目录存在、规则加载成功和代理 Running 都不是采集成功的充分证据。

## 2. 轮转与检查点是两件事

用连续合成序号分别验证 rename/create 与 copytruncate，不假定同样配置能覆盖两者。检查旧文件最后几行、新文件最初几行、短寿命文件、快速多次轮转和文件名复用。为每个用例保存源端期望集合与后端实际集合，单独报告缺失、重复和乱序。

检查点用于恢复读取进度，缓冲用于保存尚未完成下游交付的数据；有偏移记录不代表有持久化缓冲，有持久化缓冲也不等于后端已经接收。需要明确状态存放位置、持久化时机、重启后保留方式及损坏处理。Fluent Bit Tail 的文件偏移数据库是一个具体例子，不应拿它推断其他采集器的实现。[Tail 文档](https://docs.fluentbit.io/manual/data-pipeline/inputs/tail)

测试代理正常重启、强制终止与配置更新时，应观察恢复位置和重复窗口。再独立测试节点丢失：本地持久化只能覆盖其持久化介质仍可用的情形，不能推导跨节点恢复能力。

## 3. 下游中断时，数据究竟停在哪里

为每一跳写清：队列在内存还是磁盘、容量与水位、是否背压、重试上限、不可重试错误、磁盘耗尽后的行为、恢复排空速度。容量估算至少考虑峰值输入速率、计划承受的中断时间和编码开销；这个估算是测试起点，不是保证。

分别模拟超时、连接拒绝、限流和无效数据拒收。恢复连接后不仅看新增日志，还要核对中断期间积压是否排空。有重试会引入重复可能，有限重试可能结束于丢弃；不能直接宣称 exactly-once。LoongCollector Loki 插件公开参数包含最大重试次数，因此必须按选定版本检查耗尽策略。[v3.4.1 Loki 插件](https://github.com/alibaba/loongcollector/blob/v3.4.1/docs/cn/plugins/flusher/extended/flusher-loki.md)

## 4. 长行、多行与时间

- **长行**：测试边界前、边界上、边界后的长度，核对截断、跳过、拆分或拒收行为是否可见；不能只看进程没有崩溃。
- **多行**：区分运行时分片重组与应用堆栈合并。测试交错输出、无末尾换行、超时 flush、轮转中断，以及不同容器是否会被误合并。
- **时间**：保留原始时间字符串与解析结果的关系。覆盖 UTC、显式时区、缺失时区、不同精度和解析失败；区分应用事件时间、采集时间与后端可查时间。
- **内容**：使用合成中文、转义符、空行与结构化字段检查编码。脱敏失败不应通过“先上传全部内容再说”解决。

每种拒收或回退都应有可观测计数或样本。本文不预设跨组件统一的行长、时间窗口或多行上限，应从实际选定版本与配置提取后再测试。

## 5. 查询不完整与采集丢失要分开

一个查询页面不是全集。Loki 范围查询包含时间范围、方向和条数限制；应核对 API 原始响应与 UI 行数限制，不把达到 limit 的结果认作完整结果。[Loki HTTP API](https://grafana.com/docs/loki/latest/reference/loki-http-api/)

分页/分窗实现要验证相同时间戳的多条记录，不能简单把下一页起点设为“上一页最后时间加一”后就声称不遗漏。若服务端不提供所需稳定游标，需采用受测的重叠窗口、合成事件 ID 核对等方法；对无法排除截断的区间标记“不完整”，而非给出确定丢失率。

查询结果建议明确四种状态：成功且为空、成功但不完整、执行失败、等待中。超时、权限拒绝、语法错误不能降级成“暂无日志”。对临界时间范围先检查时间解析与时钟偏差，再判断采集遗漏。`kubectl logs` 也不是历史日志全集：官方说明它仅返回当前最新轮转文件的内容。[Kubernetes 日志轮转](https://kubernetes.io/docs/concepts/cluster-administration/logging/)
