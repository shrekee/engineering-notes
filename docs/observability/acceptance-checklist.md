# 验收清单：以证据关闭未知项

**状态：以下全部是建议测试，尚未执行。** 勾选表示该项已有可复核证据，而不是“配置看起来正确”。测试必须在获授权的环境进行，公开报告仅使用合成数据。

## 1. 先约定验收口径

- [ ] 固定 Kubernetes、运行时、采集器、插件、Loki、Prometheus 与 Grafana 的版本和配置摘要。
- [ ] 明确采集范围、排除项、目标节点集合、允许的延迟/重复/缺失边界及保留时长；阈值由使用方填写，不由本文虚构。
- [ ] 生成包含 `test_run`、单调 `sequence`、事件时间与来源标识的合成数据；保留独立源端期望集合。不要把高基数测试 ID 默认设为 Loki 索引标签。
- [ ] 定义对账区间和等待完成条件；排除仍在缓冲、查询截断、时间解析偏移等歧义后再计算缺失。
- [ ] 将原始查询参数、错误、版本和证据索引纳入记录；机密配置与真实业务数据不得进入公开报告。

## 2. 采集与恢复矩阵

| 待验证项 | 操作或条件 | 所需证据 |
| --- | --- | --- |
| stdout/stderr | 多容器、重启、短任务；确认两种输出都在范围内 | 来源身份正确、序号可对账、无跨容器误合并 |
| 应用文件 | 普通文件、共享卷、可写层分别测试；加入不匹配反例 | 可见性、权限、发现延迟和排除规则各有证据 |
| 节点覆盖 | 不同节点池、污点、调度限制及新加入节点 | 应覆盖节点与实际采集目标逐项对应，而非仅数 Pod |
| 轮转 | rename/create、copytruncate、快速轮转、文件名复用 | 轮转前后序号、重复与缺失区间明确 |
| 检查点 | 正常重启、异常退出、配置更新及状态不可读 | 恢复位置与故障行为可解释；状态卷不是误设为临时卷 |
| 缓冲与中断 | 下游超时、限流、拒收、持续中断后恢复 | 水位、丢弃/重试计数、恢复排空与实际对账一致 |
| 容量边界 | 达到队列/磁盘预算；仅限隔离环境 | 背压或丢弃行为明确，告警可触发，不影响无关工作负载 |
| 长行 | 测试配置上限前后及 Unicode 字符 | 字节/字符口径明确，截断或跳过有可见信号 |
| 多行 | 堆栈、运行时分片、交错、无末尾换行 | 不串容器，超时结束有定义，最终文本与预期一致 |
| 时间 | 时区、精度、缺失/非法时间、时钟偏移 | 原始时间与回退策略可追溯，窗口查询可重现 |

故障恢复结果应分别列出：期望条数、唯一观测条数、缺失 ID、重复 ID、不可判定区间和可查延迟。一次稳定条件下的全量匹配，只证明该次测试通过，不证明任意故障下 exactly-once。风险解释见[采集易错点](collection-pitfalls.md)。

## 3. 查询与界面

- [ ] 按时间、命名空间、工作负载、Pod 身份与容器定位日志；跨重建不混淆对象。
- [ ] 查询超过页面/API 行数限制时能够提示不完整；分页与分窗测试覆盖相同时间戳多条记录。
- [ ] 同样的合成输入在 API 和 UI 中可以对账；UI 截断不被错误归因于采集丢失。
- [ ] 分别验证成功空集、权限拒绝、语法错误、超时和后端故障；错误不会被显示为“暂无数据”。
- [ ] 日志保留与清理行为符合约定；同时验证超出保留窗口的不可查预期，不能仅验证写入。
- [ ] 数据源和查询页不泄漏令牌；只读用户不能修改采集配置或绕过数据访问边界。

查询参数与权限职责依据 [Loki HTTP API](https://grafana.com/docs/loki/latest/reference/loki-http-api/)；具体分页策略仍须测试，本文未提供通用无损分页实现。

## 4. 指标、Events 与权限

- [ ] 资源使用来自已确认的 kubelet/运行时统计路径，对象状态来自 KSM；metrics-server 不被当成历史监控库。
- [ ] CPU、内存、requests/limits 单位与分母正确；无 limit、零值、缺失样本、重启和重复抓取都有处理。
- [ ] 抓取目标消失或鉴权失败时，显示缺失/陈旧而非健康的零值；告警与恢复通知经过演练。
- [ ] Events 的对象关联、重连、重复/更新和保留窗口经过验证；与应用日志可区分，未被描述为 tracing。
- [ ] 节点目录、状态目录和运行时接口各自最小授权；没有以采集方便为由无条件开放宿主机写权限。
- [ ] API RBAC、后端读写身份、网络边界分别测试允许与拒绝场景；租户或标签选择不能替代授权。
- [ ] 标签基数和流数量有预算与观测；请求 ID、用户 ID、完整 URL 等无界字段未误入索引。
- [ ] 对合成敏感字段做脱敏反例测试，确认原文未进入不应接收它的后端。

## 5. 记录模板与停止条件

每个用例记录：**状态（未执行/通过/失败/不可判定）、版本与配置摘要、输入集合、执行步骤、预期、实际、证据位置、限制、负责人、下一步**。失败与不可判定不允许合并成通过；不适用项写清原因。

若存在未解释的缺失、查询截断、权限越界或节点覆盖缺口，应暂停扩大接入，先收敛问题。完成条件是约定范围内每项都有结果或明确接受的限制，并且回退与维护责任已确认；不是 Grafana 出现第一条日志。
